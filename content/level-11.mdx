## LEFT JOIN: একটা টেবিলের সবাই থাকবে

`INNER JOIN` তখনই ঠিক, যখন শুধু মিল থাকা রেকর্ড দরকার। কিন্তু ব্যবসার চাহিদা প্রায়ই এর বেশি।

মার্কেটিং টিম বলল: **"প্রতিটা কাস্টমারের একটা রিপোর্ট চাই, যাঁরা এখনো প্রথম অর্ডার দেননি তাঁরাও।"** `INNER JOIN` দিলে Nabila আর Tanvir হারিয়ে যান, কারণ তাঁদের কোনো অর্ডার নেই। কিন্তু ঠিক তাঁদেরকেই তো অফার পাঠাতে হবে!

এখানেই `LEFT JOIN`। সে **বাঁ পাশের টেবিলের প্রতিটা Row রাখে**, আর ডান পাশে মিল পেলে সেই তথ্য পাশে বসায়:

<Run db="join-shop">
```sql
SELECT c.name, o.order_id, o.order_date, o.amount
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id
ORDER BY c.customer_id, o.order_id;
```
</Run>

| name | order_id | order_date | amount |
| --- | --- | --- | --- |
| Rahim | 101 | 2026-01-05 | 900.00 |
| Rahim | 102 | 2026-01-12 | 1800.00 |
| Karim | 103 | 2026-02-03 | 1200.00 |
| Karim | 107 | 2026-04-01 | 1800.00 |
| Sumaiya | 104 | 2026-02-20 | 2500.00 |
| Sumaiya | 105 | 2026-03-08 | 1350.00 |
| Nabila | NULL | NULL | NULL |
| Tanvir | NULL | NULL | NULL |

অর্ডার দেওয়া কাস্টমারদের পাশে তাঁদের অর্ডার। যাঁরা দেননি, তাঁরাও আছেন, কিন্তু অর্ডারের সব ঘরে `NULL`। এই `NULL` মানে কোনো ভুল না; শুধু বলছে: **"এই কাস্টমারের জন্য কোনো মিলে-যাওয়া অর্ডার পাইনি।"**

### কোন টেবিল বাঁয়ে? নিজেকে একটা প্রশ্ন করো

`LEFT JOIN`-এ **টেবিলের ক্রম গুরুত্বপূর্ণ।** `FROM`-এর পরে যে টেবিল, সেটাই পুরোটা রক্ষা পায়। কোনটা বাঁয়ে বসবে, ঠিক করার সহজ উপায়:

> **"আমার রিপোর্টের প্রতিটা Row আসলে কী?"**

রিপোর্ট কাস্টমারদের নিয়ে? `customers` দিয়ে শুরু করো। পণ্য নিয়ে? `products` দিয়ে। এই **মূল টেবিল** চিনে ফেললে কোন JOIN লাগবে, সেটা অর্ধেক ঠিক হয়ে যায়। (লেভেল ৫.১-এ এটাকেই বলেছি উত্তরের "গ্রেইন"।)

### LEFT JOIN দিয়ে সবার হিসাব

প্রত্যেক কাস্টমার কয়টা অর্ডার দিয়েছেন, কেউ বাদ যাবে না:

<Run db="join-shop">
```sql
SELECT c.name,
       COUNT(o.order_id)        AS orders,
       COALESCE(SUM(o.amount), 0) AS total
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id
GROUP BY c.customer_id, c.name
ORDER BY total DESC, c.customer_id;
```
</Run>

| name | orders | total |
| --- | --- | --- |
| Sumaiya | 2 | 3850.00 |
| Karim | 2 | 3000.00 |
| Rahim | 2 | 2700.00 |
| Nabila | 0 | 0 |
| Tanvir | 0 | 0 |

দুটো সূক্ষ্ম জিনিস:

- `COUNT(*)` না, `COUNT(o.order_id)`। Nabila-র জন্যও একটা Row আছে (সব `NULL` নিয়ে), তাই `COUNT(*)` তাঁকে **১** দেখাত। `COUNT(Column)` `NULL` গোনে না, তাই সঠিক উত্তর ০।
- `SUM` কিছু না পেলে `NULL` দেয়; `COALESCE(..., 0)` সেটাকে ০ বানায়। (MySQL-এ `IFNULL`-ও চলে।)

## RIGHT JOIN: উল্টো দিক

`RIGHT JOIN` ঠিক `LEFT JOIN`-এর উল্টো: **ডান পাশের টেবিলের প্রতিটা Row রাখে।** ধরো রিপোর্ট প্রতিটা **অর্ডার** নিয়ে, আর কাস্টমারের তথ্য পাওয়া গেলে পাশে বসবে:

<Run db="join-shop">
```sql
SELECT o.order_id, o.amount, c.name
FROM customers c
RIGHT JOIN orders o ON o.customer_id = c.customer_id
ORDER BY o.order_id;
```
</Run>

৭টা অর্ডারই আছে। 106-এর পাশে `name` `NULL`, কারণ তার কাস্টমার পাওয়া যায়নি। আর Nabila, Tanvir এবার নেই: ডান পাশ (`orders`) রক্ষা পেয়েছে, বাঁ পাশ না।

<JoinMatch mode="right" />

তবে আসল প্রজেক্টে `RIGHT JOIN` খুব কমই দেখবে। বেশির ভাগ ডেভেলপার টেবিলের ক্রম উল্টে `LEFT JOIN` লেখেন:

<Run db="join-shop">
```sql
-- একই ফলাফল, শুধু টেবিলের ক্রম বদলে LEFT JOIN
SELECT o.order_id, o.amount, c.name
FROM orders o
LEFT JOIN customers c ON c.customer_id = o.customer_id
ORDER BY o.order_id;
```
</Run>

হুবহু একই উত্তর। `A RIGHT JOIN B` আর `B LEFT JOIN A` একই জিনিস। সবসময় `LEFT JOIN` লিখলে লেখার ধরন একরকম থাকে, আর বড় Query পড়া সহজ হয়: "মূল টেবিল সবসময় সবার আগে"। `LEFT JOIN`-এ স্বচ্ছন্দ হলে `RIGHT JOIN` নিজে লেখার দরকার প্রায় পড়বেই না।

## FULL JOIN: দুই পাশের সবাই

এবার অডিট টিম বলল: **"ডেটার পুরো ছবি চাই: প্রতিটা কাস্টমার আর প্রতিটা অর্ডার, মিল থাকুক বা না থাকুক।"** হারানো বা বেখাপ্পা রেকর্ড খুঁজতে এই চাহিদা খুব সাধারণ।

`FULL JOIN` (পুরো নাম `FULL OUTER JOIN`) ঠিক এই কাজের জন্য। মিল পেলে এক Row-এ জোড়ে; কাস্টমারের অর্ডার না থাকলেও কাস্টমার আসেন; অর্ডারের কাস্টমার না থাকলেও অর্ডার আসে; ফাঁকা ঘরে `NULL`।

<JoinMatch mode="full" />

`LEFT` আর `RIGHT`-এর মতো এখানে **টেবিলের ক্রমে কিছু যায় আসে না**, কারণ দুই পাশই সমান গুরুত্ব পায়। লক্ষ্য একটাকে রক্ষা করা না, **সবকিছু রক্ষা করা।**

<JoinVenn kind="full" />

### MySQL-এ FULL JOIN নেই, বানিয়ে নাও

PostgreSQL বা SQL Server-এ সরাসরি লেখা যায়:

```sql
-- MySQL-এ চলবে না: ERROR 1064
SELECT c.name, o.order_id
FROM customers c
FULL OUTER JOIN orders o ON o.customer_id = c.customer_id;
```

**MySQL-এ `FULL OUTER JOIN` নেই।** সমাধান: দুই পাশের `LEFT JOIN` জোড়া দাও `UNION ALL` দিয়ে (লেভেল ১০-এর "বেশি Row"!)। প্রথম অংশে কাস্টমারের সবাই (মিলসহ), দ্বিতীয় অংশে শুধু সেই অর্ডারগুলো, যাদের কাস্টমার নেই:

<Run db="join-shop">
```sql
-- ১: সব কাস্টমার, মিললে অর্ডারসহ
SELECT c.name, o.order_id, o.amount
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id

UNION ALL

-- ২: শুধু কাস্টমারহীন অর্ডার (মিলগুলো প্রথম অংশে এসেই গেছে)
SELECT c.name, o.order_id, o.amount
FROM orders o
LEFT JOIN customers c ON c.customer_id = o.customer_id
WHERE c.customer_id IS NULL

ORDER BY order_id, name;
```
</Run>

৯টা Row: ৬টা মিল, ২ জন অর্ডারহীন কাস্টমার (ওপরে, কারণ ছোট থেকে বড় সাজালে `NULL` আগে আসে), ১টা কাস্টমারহীন অর্ডার। শেষের `ORDER BY` পুরো `UNION ALL`-এর ফলাফলকে সাজায়, শুধু দ্বিতীয় অংশকে না।

অনেক বইয়ে দেখবে `LEFT JOIN ... UNION ... RIGHT JOIN`। সেটাও কাজ করে, কারণ `UNION` দুই অংশে আসা মিলগুলোর ডুপ্লিকেট মুছে দেয়। কিন্তু দুটো সত্যিকারের একই রকম Row থাকলে `UNION` সেগুলোকেও এক করে ফেলে। ওপরের `UNION ALL` + `IS NULL` রূপটা সবসময় নিরাপদ।

<Remember>
**কী রাখতে চাও, সেটা দিয়ে JOIN বাছো।** শুধু মিল থাকা রেকর্ড: `INNER JOIN`। একটা টেবিল মূল, তার সবাই চাই: `LEFT JOIN` (মূলটা বাঁয়ে)। দুই টেবিলের সবাই, মিল থাকুক বা না থাকুক: `FULL JOIN` (MySQL-এ `LEFT ... UNION ALL ...`)।
</Remember>

## Anti Join: কী **মেলে না**

এ পর্যন্ত প্রতিটা JOIN মিল খোঁজার জন্য। কিন্তু অনেক সময় সবচেয়ে দামি তথ্য হলো **যা নেই**:

- সেলস ম্যানেজার: "কোন কাস্টমাররা **কখনো** অর্ডার দেননি?"
- ইনভেন্টরি টিম: "কোন পণ্য **একবারও** বিক্রি হয়নি?"

এখানে মিলে-যাওয়া রেকর্ড নিয়ে আগ্রহ নেই; খুঁজছি সেই রেকর্ড, যার সাথে অন্য টেবিলে কোনো সম্পর্কিত রেকর্ড **নেই**। এটাই **Anti Join**।

SQL-এ `ANTI JOIN` নামে কোনো শব্দ নেই। একই কাজ হয় দুই ধাপে: **(১) JOIN করো, (২) শুধু সেই Row রাখো যেখানে মিল পাওয়া যায়নি।** মিল না পেলে ডান পাশের সব ঘর `NULL` হয়; তাই `NULL`-গুলোই উত্তর।

### বাঁ পাশের Anti Join: অর্ডারহীন কাস্টমার

<Run db="join-shop">
```sql
SELECT c.customer_id, c.name, c.city
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id
WHERE o.order_id IS NULL;
```
</Run>

| customer_id | name | city |
| --- | --- | --- |
| 4 | Nabila | Sylhet |
| 5 | Tanvir | Khulna |

`customers` দিয়ে শুরু, কারণ ফেরত চাই কাস্টমারই। প্রতিটা কাস্টমারের অর্ডার খোঁজা হলো; না পেলে অর্ডারের ঘর `NULL`; `IS NULL` দিয়ে ছাঁকার পর থাকলেন শুধু যাঁরা কখনো অর্ডার দেননি।

<JoinMatch mode="left-anti" />

`IS NULL` পরীক্ষা করো ডান টেবিলের এমন Column-এ, যেটা নিজে থেকে কখনো `NULL` হয় না: Primary Key (`o.order_id`) বা JOIN-এর Column। নাহলে "আসলে মিল আছে, শুধু ঘরটা ফাঁকা" এমন Row-ও ভুল করে চলে আসবে।

### ডান পাশের Anti Join: কাস্টমারহীন অর্ডার

ভালোভাবে বানানো Database-এ এটা হওয়ার কথা না, কিন্তু বাইরের সিস্টেম থেকে ডেটা আনলে বা পুরোনো রেকর্ড অডিট করতে গেলে প্রায়ই পাওয়া যায়। যুক্তি হুবহু এক, শুধু **কোন টেবিল পরীক্ষা করছ সেটা বদলাও**। আর `RIGHT JOIN` না লিখে টেবিল উল্টে `LEFT JOIN`:

<Run db="join-shop">
```sql
SELECT o.order_id, o.customer_id, o.amount
FROM orders o
LEFT JOIN customers c ON c.customer_id = o.customer_id
WHERE c.customer_id IS NULL;
```
</Run>

অর্ডার 106, কাস্টমার ৯, যিনি নেই।

<JoinMatch mode="right-anti" />

### দুই পাশের Anti Join: একটা অডিট রিপোর্ট

একসাথে দুটোই চাই: অর্ডারহীন কাস্টমার **আর** কাস্টমারহীন অর্ডার। একে বলে **Full Anti Join**: FULL JOIN করে মিলগুলো বাদ দেওয়া। MySQL-এ দুই Anti Join-কে `UNION ALL` দিয়ে নিচে নিচে বসাও, সাথে একটা লেবেল:

<Run db="join-shop">
```sql
SELECT 'অর্ডারহীন কাস্টমার' AS problem, c.customer_id AS id, c.name AS detail
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id
WHERE o.order_id IS NULL

UNION ALL

SELECT 'কাস্টমারহীন অর্ডার', o.order_id, CONCAT('customer_id = ', o.customer_id)
FROM orders o
LEFT JOIN customers c ON c.customer_id = o.customer_id
WHERE c.customer_id IS NULL;
```
</Run>

ডেটার মান যাচাই আর দুই টেবিলের অসঙ্গতি খোঁজায় এই ধরনের Query খুব কাজের।

<JoinVenn kind="full-anti" />

<Tip title="আরেকটা লেখা: NOT EXISTS">
Anti Join `NOT EXISTS` দিয়েও লেখা যায় (লেভেল ১২): `WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id)`। ফলাফল একই। কিন্তু `NOT IN (SELECT customer_id FROM orders)` থেকে সাবধান: ভেতরের তালিকায় একটা `NULL` থাকলেই কেউ আসে না।
</Tip>

মনে রাখার সহজ উপায়: **"কী মেলে?" না, জিজ্ঞেস করছ "কী মেলে না?"** এই ধারণাটা ধরতে পারলে প্রতিটা Anti Join একই ছাঁচের।

## CROSS JOIN: প্রতিটার সাথে প্রতিটা

এবার একদম আলাদা একটা JOIN। আগের সবগুলো দুই টেবিলের **সম্পর্ক** খুঁজেছে। `CROSS JOIN` খোঁজে না: সে **সব সম্ভাব্য জোড়া** বানায়। একটায় ৫টা Row আর অন্যটায় ৪টা হলে ফলাফল ২০টা।

কাজে লাগে কোথায়? ধরো একটা পোশাকের দোকান। একটা টেবিলে পণ্য (T-shirt, Hoodie, Jacket), আরেকটায় সাইজ (S, M, L, XL)। প্রতিটা পণ্যের প্রতিটা সাইজের একটা তালিকা (স্টক বা দামের জন্য) হাতে লিখতে হবে না:

<CrossGrid />

<Run db="join-shop">
```sql
SELECT COUNT(*) AS combinations
FROM products
CROSS JOIN sizes;
```
</Run>

৫ × ৪ = ২০। এবার শুধু পোশাক, সাইজের ক্রমে সাজিয়ে:

<Run db="join-shop">
```sql
SELECT p.product_name, s.size_code
FROM products p
CROSS JOIN sizes s
WHERE p.category = 'Clothing'
ORDER BY p.product_id, s.sort_order;
```
</Run>

১২টা জোড়া, একটাও হাতে লিখতে হয়নি। `ON` নেই, কারণ মেলানোর কিছু নেই।

যেহেতু সব জোড়া তৈরি হয়, Row-এর সংখ্যা খুব দ্রুত বাড়ে। তাই `CROSS JOIN` মূলত জোড়া তৈরি, সিমুলেশন আর টেস্ট ডেটা বানানোর কাজে; বড় টেবিলে সাবধান। আর লেভেল ১০-এর সেই `ON` ভুলে যাওয়া Query? সেটা আসলে অনিচ্ছাকৃত `CROSS JOIN`।

## অনেকগুলো টেবিল একসাথে

এ পর্যন্ত একবারে দুটো টেবিল। আসল অ্যাপে প্রায়ই তিন, চার, বা আরো বেশি টেবিল এক Query-তে জোড়া লাগে।

লেভেল ১০-এর শুরুর প্রশ্নে ফিরি, এবার একটু বড় করে। ম্যানেজার চাইছেন একটা সেলস রিপোর্ট: **কাস্টমারের নাম, কোন পণ্য কিনেছেন, অর্ডারের তারিখ, আর কোন কর্মী অর্ডারটা প্রসেস করেছেন।** কাস্টমার `customers`-এ, পণ্য `products`-এ, অর্ডার `orders`-এ, কর্মী `employees`-এ। চারটা টেবিল।

সবচেয়ে সহজ উপায়: আগে **মূল টেবিল** ঠিক করো। "রিপোর্টের প্রতিটা Row কী?" এখানে প্রতিটা Row = **একটা অর্ডার**। তাই শুরু `orders` দিয়ে, তারপর বাকিগুলো জুড়ে কাস্টমার, পণ্য আর কর্মীর তথ্য আনো:

<JoinSchema focus="orders" />

<Run db="join-shop">
```sql
SELECT o.order_id, c.name AS customer, p.product_name AS product,
       o.order_date, e.name AS processed_by
FROM orders o
JOIN customers c ON c.customer_id = o.customer_id
JOIN products  p ON p.product_id  = o.product_id
JOIN employees e ON e.employee_id = o.employee_id
ORDER BY o.order_id;
```
</Run>

| 102 | Rahim | Headphone | 2026-01-12 | Rony |
| 103 | Karim | Hoodie | 2026-02-03 | Shakil |

নতুন কিছু না: **প্রতিটা নতুন টেবিলের জন্য একটা করে `JOIN ... ON ...`**, সেই একই কাজের পুনরাবৃত্তি। চারটা টেবিল মানে তিনটা `JOIN`।

কিন্তু একটা অর্ডার কম! **106 নেই।** "প্রতিটা Row একটা অর্ডার" বলেছিলাম, অথচ একটা অর্ডার হারিয়ে গেল, কারণ `customers`-এর সাথে `INNER JOIN` তাকে ফেলে দিয়েছে। রিপোর্টে প্রতিটা অর্ডার রাখতে হলে সেই জোড়াটা `LEFT JOIN`:

<Run db="join-shop">
```sql
SELECT o.order_id, COALESCE(c.name, '(অজানা কাস্টমার)') AS customer,
       p.product_name AS product, o.order_date, e.name AS processed_by
FROM orders o
LEFT JOIN customers c ON c.customer_id = o.customer_id
JOIN products  p ON p.product_id  = o.product_id
JOIN employees e ON e.employee_id = o.employee_id
ORDER BY o.order_id;
```
</Run>

৭টা, 106 ফিরে এসেছে। **প্রতিটা জোড়ার জন্য আলাদা করে জিজ্ঞেস করো: এখানে মিল না পেলে Row-টা ফেলে দেব, নাকি রাখব?**

<BugMonster title="শিকলে একটা INNER, পুরো LEFT নষ্ট">
`A LEFT JOIN B ... JOIN C ON C.x = B.y` লিখলে, যেখানে B পাওয়া যায়নি (`B.y` `NULL`) সেখানে C-ও মিলবে না, আর পরের সাধারণ `JOIN` সেই Row ফেলে দেবে। `LEFT JOIN` দিয়ে কাউকে বাঁচালে, **তার ওপর নির্ভর করা পরের সব জোড়াও `LEFT JOIN`** রাখো। (ওপরে `products` আর `employees` সরাসরি `orders`-এর সাথে জোড়া, `customers`-এর সাথে না, তাই সাধারণ `JOIN` নিরাপদ।)
</BugMonster>

## দুটো জরুরি সূক্ষ্মতা

### LEFT JOIN-এ শর্ত: ON-এ নাকি WHERE-এ?

প্রতিটা কাস্টমার, আর মার্চ ২০২৬ বা তার পরের অর্ডার (না থাকলে খালি):

<Run db="join-shop">
```sql
-- ✅ অর্ডারের শর্ত ON-এ
SELECT c.name, o.order_id, o.order_date
FROM customers c
LEFT JOIN orders o
       ON o.customer_id = c.customer_id
      AND o.order_date >= '2026-03-01'
ORDER BY c.customer_id;
```
</Run>

৫ জনই আছেন: Karim (107), Sumaiya (105), বাকিদের পাশে `NULL`। এবার একই শর্ত `WHERE`-এ:

<Run db="join-shop">
```sql
-- ❌ অর্ডারের শর্ত WHERE-এ
SELECT c.name, o.order_id, o.order_date
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id
WHERE o.order_date >= '2026-03-01'
ORDER BY c.customer_id;
```
</Run>

মাত্র ২ জন! `WHERE` চলে JOIN-এর **পরে**। Rahim, Nabila, Tanvir-এর Row-এ তারিখ ছিল আগের বা `NULL`; `NULL >= ...` সত্য না, তাই `WHERE` তাঁদের ফেলে দিল। ফলে `LEFT JOIN` চুপচাপ `INNER JOIN` হয়ে গেল।

<Remember>
**`LEFT JOIN`-এ ডান টেবিলের শর্ত `ON`-এ লেখো, `WHERE`-এ না।** `WHERE`-এ ডান টেবিলের Column-এর শর্ত দিলে (শুধু Anti Join-এর `IS NULL` ছাড়া) তোমার `LEFT JOIN` নিঃশব্দে `INNER JOIN` হয়ে যায়। বাঁ টেবিলের শর্ত (যেমন `c.city = 'Dhaka'`) `WHERE`-এই থাকবে।
</Remember>

### Self Join: একটা টেবিল, দুটো ভূমিকা

`employees.manager_id` দেখায় `employees`-কেই: প্রত্যেক কর্মীর ম্যানেজারও একজন কর্মী। প্রত্যেকের পাশে তাঁর ম্যানেজারের নাম চাই। একই টেবিল দুবার, দুটো আলাদা Alias দিয়ে, যেন দুটো আলাদা টেবিল:

<Run db="join-shop">
```sql
SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m ON m.employee_id = e.manager_id
ORDER BY e.employee_id;
```
</Run>

| employee | manager |
| --- | --- |
| Mitu | NULL |
| Shakil | Mitu |
| Rony | Mitu |
| Lipi | Shakil |

`e` হলো "কর্মী হিসেবে" টেবিলটা, `m` হলো "ম্যানেজার হিসেবে"। `LEFT JOIN` দিয়েছি যাতে Mitu (যাঁর কোনো ম্যানেজার নেই) বাদ না পড়েন। কোনো নতুন JOIN না; শুধু একই টেবিলের দুটো কপি।

<Analogy>
কর্মীদের তালিকার দুটো ফটোকপি নাও। বাঁ হাতের কপিতে প্রত্যেকের পাশে লেখা "ম্যানেজারের নম্বর"। ডান হাতের কপিতে সেই নম্বর খুঁজে নাম পড়ো। কাগজ একটাই, দুটো কপি দুই কাজে।
</Analogy>

## সারসংক্ষেপ: কী রাখতে চাও?

<JoinVennGrid />

| প্রয়োজন | JOIN |
| --- | --- |
| শুধু দুই পাশে মিল থাকা রেকর্ড | `INNER JOIN` |
| একটা টেবিল মূল, তার প্রতিটা Row চাই | `LEFT JOIN` (মূলটা বাঁয়ে) |
| উল্টো দিকের সবাই | `RIGHT JOIN`, বা টেবিল উল্টে `LEFT JOIN` |
| দুই টেবিলের সবাই, মিল থাকুক বা না থাকুক | `FULL JOIN` (MySQL-এ `LEFT … UNION ALL …`) |
| যাদের মিল **নেই** | Anti Join: `LEFT JOIN … WHERE ডান.key IS NULL` |
| সব সম্ভাব্য জোড়া | `CROSS JOIN` |
| একই টেবিলের দুটো ভূমিকা | Self Join (দুটো Alias) |

JOIN-এর নাম মুখস্থ করা বন্ধ করে **ব্যবসার প্রশ্নটা** নিয়ে ভাবো ("রিপোর্টের প্রতিটা Row কী? কাকে কোনোভাবেই হারানো চলবে না?"), সঠিক JOIN বাছাই তখন অনেক সহজ।

<BugMonster title="বাইরের JOIN-এর ফাঁদ">

**১. `LEFT JOIN`-এর পর `COUNT(*)`।** মিলহীন Row-ও ১ গোনা হয়। ডান টেবিলের কোনো Column গোনো: `COUNT(o.order_id)`।

**২. `WHERE`-এ ডান টেবিলের শর্ত।** ওপরে দেখলে: `LEFT JOIN` চুপচাপ `INNER` হয়ে যায়। ফলাফলে "বাদ পড়া"-রা আসছে না দেখলে প্রথমেই এটা সন্দেহ করো।

**৩. MySQL-এ `FULL OUTER JOIN` লিখে error।** নেই; `LEFT JOIN ... UNION ALL ... (উল্টো LEFT JOIN ... IS NULL)`।

**৪. Anti Join-এ ভুল Column-এ `IS NULL`।** যে Column এমনিতেই `NULL` হতে পারে, সেটায় দিলে মিল থাকা Row-ও চলে আসে। Primary Key বা JOIN-এর Column-এ দাও।

**৫. `CROSS JOIN` বড় টেবিলে।** ১০,০০০ × ১০,০০০ = ১০ কোটি Row। আগে `COUNT(*)` দেখে নাও।

</BugMonster>

<Solution>
```sql
SELECT p.product_id, p.product_name, p.price
FROM products p
LEFT JOIN orders o ON o.product_id = p.product_id
WHERE o.order_id IS NULL;
```

<Quest id="2" title="কর্মীদের কাজের হিসাব">
প্রত্যেক কর্মী কয়টা অর্ডার প্রসেস করেছেন আর মোট কত টাকার, যিনি একটাও করেননি তিনিও (০ দেখাবে)।

<Quest id="3" title="প্রতিটা পোশাকের সাইজ-তালিকা, স্টক শূন্য দিয়ে">
প্রতিটা Clothing পণ্যের প্রতিটা সাইজের জন্য একটা Row, সাথে `stock` নামে একটা Column যেখানে শুরুতে ০।

</Solution>

<Boss title="ডেটা-অডিট রিপোর্ট">
একটাই Query-তে দোকানের সব "একা" রেকর্ডের তালিকা, একটা `problem` Column সহ: (ক) যে কাস্টমার কখনো অর্ডার দেননি, (খ) যে অর্ডারের কাস্টমার নেই, (গ) যে পণ্য কখনো বিক্রি হয়নি, (ঘ) যে কর্মী কোনো অর্ডার প্রসেস করেননি।

<Solution title="ইঙ্গিত">
প্রতিটা অংশ একটা আলাদা Anti Join (`LEFT JOIN ... WHERE ... IS NULL`)। চারটাকে নিচে নিচে বসাও: বেশি Row, মানে `UNION ALL`। প্রতিটা অংশে Column-এর সংখ্যা আর ধরন এক রাখো।
</Solution>

<Solution>
<Run db="join-shop">
```sql
SELECT 'অর্ডারহীন কাস্টমার' AS problem, c.name AS item
FROM customers c LEFT JOIN orders o ON o.customer_id = c.customer_id
WHERE o.order_id IS NULL
UNION ALL
SELECT 'কাস্টমারহীন অর্ডার', CONCAT('#', o.order_id)
FROM orders o LEFT JOIN customers c ON c.customer_id = o.customer_id
WHERE c.customer_id IS NULL
UNION ALL
SELECT 'বিক্রি হয়নি এমন পণ্য', p.product_name
FROM products p LEFT JOIN orders o ON o.product_id = p.product_id
WHERE o.order_id IS NULL
UNION ALL
SELECT 'কাজহীন কর্মী', e.name
FROM employees e LEFT JOIN orders o ON o.employee_id = e.employee_id
WHERE o.order_id IS NULL;
```
</Run>
