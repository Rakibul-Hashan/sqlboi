## AND: দুটোই সত্যি হতে হবে

```sql
SELECT name, class, city, gpa FROM students
WHERE class = 8 AND city = 'ঢাকা';
```

| name | class | city | gpa |
| --- | --- | --- | --- |
| রাফি | 8 | ঢাকা | 4.50 |
| তানভীর | 8 | ঢাকা | 3.75 |

## OR: যেকোনো একটা সত্যি হলেই চলবে

```sql
SELECT name, class, city FROM students
WHERE class = 10 OR city = 'ঢাকা';
```

| name | class | city |
| --- | --- | --- |
| রাফি | 8 | ঢাকা |
| তানভীর | 8 | ঢাকা |
| সাদিয়া | 9 | ঢাকা |
| জুবায়ের | 10 | খুলনা |
| ফারিহা | 10 | চট্টগ্রাম |
| ইমরান | 10 | ঢাকা |

ইমরান দুটো শর্তই পূরণ করে, তবু একবারই এসেছে।

## NOT: উল্টে দাও

```sql
SELECT name, gpa FROM students WHERE NOT gpa >= 4.00;
```

| name | gpa |
| --- | --- |
| তানভীর | 3.75 |
| আরিফ | 2.90 |
| জুবায়ের | 3.50 |

ফারিহা নেই। তার GPA `NULL`, তাই `gpa >= 4.00` হলো "জানা নেই", আর "জানা নেই"-এর উল্টোও "জানা নেই"।

## অগ্রাধিকার: কে আগে?

গণিতে `2 + 3 × 4` = 14, কারণ গুণ যোগের আগে হয়। SQL-এও এমন নিয়ম আছে:

| অগ্রাধিকার | অপারেটর |
| --- | --- |
| সবচেয়ে বেশি | `( )` বন্ধনী |
| ↓ | `*` `/` `%`, তারপর `+` `-` |
| ↓ | `=` `<>` `<` `>` `<=` `>=` `LIKE` `IN` `IS` `BETWEEN` |
| ↓ | `NOT` |
| ↓ | `AND` |
| সবচেয়ে কম | `OR` |

মানে **`AND` সবসময় `OR`-এর আগে কাজ করে**, ঠিক যেমন গুণ যোগের আগে।

### একটা সত্যিকারের ভুল

হেডস্যার বললেন, "ঢাকা বা চট্টগ্রামের ছাত্রদের মধ্যে যাদের GPA 4.50 বা বেশি, তাদের বৃত্তি দাও।" নতুন প্রোগ্রামার লিখল:

```sql
SELECT name, class, city, gpa FROM students
WHERE city = 'ঢাকা' OR city = 'চট্টগ্রাম' AND gpa >= 4.50;
```

| name | class | city | gpa |
| --- | --- | --- | --- |
| রাফি | 8 | ঢাকা | 4.50 |
| নুসরাত | 8 | চট্টগ্রাম | 5.00 |
| তানভীর | 8 | ঢাকা | 3.75 |
| সাদিয়া | 9 | ঢাকা | 4.80 |
| ইমরান | 10 | ঢাকা | 4.00 |

তানভীর (3.75) আর ইমরান (4.00) বৃত্তি পেয়ে গেল! কারণ `AND` আগে কাজ করায় MySQL আসলে পড়েছে:

```sql
WHERE city = 'ঢাকা' OR (city = 'চট্টগ্রাম' AND gpa >= 4.50)
```

অর্থাৎ "ঢাকার **সবাই**, অথবা চট্টগ্রামের ভালো ছাত্ররা"। ঠিক Query-তে বন্ধনী লাগবে:

```sql
SELECT name, class, city, gpa FROM students
WHERE (city = 'ঢাকা' OR city = 'চট্টগ্রাম') AND gpa >= 4.50;
```

| name | class | city | gpa |
| --- | --- | --- | --- |
| রাফি | 8 | ঢাকা | 4.50 |
| নুসরাত | 8 | চট্টগ্রাম | 5.00 |
| সাদিয়া | 9 | ঢাকা | 4.80 |

<Remember>
**`AND` আর `OR` একসাথে থাকলে সবসময় বন্ধনী দাও,** নিয়ম জানা থাকলেও। বন্ধনী Query-কে ধীর করে না, কিন্তু পরে যে পড়বে (ছয় মাস পরের তুমিও) তার কাছে উদ্দেশ্যটা পরিষ্কার করে দেয়। এই ক্ষেত্রে `IN` আরও ভালো: `WHERE city IN ('ঢাকা', 'চট্টগ্রাম') AND gpa >= 4.50`।
</Remember>

## সত্য-মিথ্যার টেবিল, NULL সহ

SQL-এ শর্তের ফলাফল তিন রকম: সত্য (`1`), মিথ্যা (`0`), আর জানা নেই (`NULL`)। একে বলে **Three-Valued Logic**।

| A | B | A AND B | A OR B |
| --- | --- | --- | --- |
| সত্য | সত্য | সত্য | সত্য |
| সত্য | মিথ্যা | মিথ্যা | সত্য |
| মিথ্যা | মিথ্যা | মিথ্যা | মিথ্যা |
| সত্য | NULL | NULL | সত্য |
| মিথ্যা | NULL | মিথ্যা | NULL |
| NULL | NULL | NULL | NULL |

যুক্তিটা সহজ: "মিথ্যা AND যাই হোক" সবসময় মিথ্যা, তাই অজানাটা কী, তাতে কিছু যায় আসে না। আবার "সত্য OR যাই হোক" সবসময় সত্য। MySQL-এ সরাসরি পরীক্ষা করে দেখো:

```sql
SELECT 1 OR 0 AND 0, (1 OR 0) AND 0, NULL AND 0, NULL OR 1, NULL AND 1;
```

| 1 OR 0 AND 0 | (1 OR 0) AND 0 | NULL AND 0 | NULL OR 1 | NULL AND 1 |
| --- | --- | --- | --- | --- |
| 1 | 0 | 0 | 1 | NULL |

প্রথম দুটো দেখাচ্ছে বন্ধনী কীভাবে উত্তর বদলে দেয়।

## De Morgan-এর সূত্র

`NOT` বন্ধনীর ভেতরে ঢুকলে `AND` হয়ে যায় `OR`, আর `OR` হয়ে যায় `AND`:

- `NOT (A OR B)` = `NOT A AND NOT B`
- `NOT (A AND B)` = `NOT A OR NOT B`

"ক্লাস ৮-এর না, আর GPA 3.00-এর কম না", এমন ছাত্র:

```sql
SELECT name, class, gpa FROM students
WHERE NOT (class = 8 OR gpa < 3.00);
-- একই জিনিস: WHERE class <> 8 AND gpa >= 3.00
```

| name | class | gpa |
| --- | --- | --- |
| মীম | 9 | 4.25 |
| সাদিয়া | 9 | 4.80 |
| জুবায়ের | 10 | 3.50 |
| ইমরান | 10 | 4.00 |

আবার ফারিহা বাদ, তার `NULL` GPA-র জন্য। `NULL` যেখানেই থাকুক, সেখানেই চোখ রাখো।

<BugMonster title="যুক্তির গোলকধাঁধা">

**১. বন্ধনী ছাড়া `OR` আর `AND`।** ওপরের বৃত্তির উদাহরণ। ফলাফল সন্দেহজনক রকম বেশি এলে প্রথমেই বন্ধনী দেখো।

**২. একই Column-এ `AND` দিয়ে দুটো মান।**

```sql
-- ❌ কেউ একসাথে ঢাকা আর সিলেটে থাকে না, তাই ফলাফল খালি
SELECT name FROM students WHERE city = 'ঢাকা' AND city = 'সিলেট';
-- ✅
SELECT name FROM students WHERE city = 'ঢাকা' OR city = 'সিলেট';
```

মানুষের ভাষায় "ঢাকা আর সিলেটের ছাত্ররা" বলি, কিন্তু SQL-এ সেটা `OR`।

**৩. `NOT`-এর ভুল জায়গা।** `NOT class = 8 AND gpa > 4` মানে `(NOT class = 8) AND gpa > 4`, কারণ `NOT` নিজের ঠিক পাশের শর্তটাকেই উল্টায়। পুরোটা উল্টাতে চাইলে `NOT (class = 8 AND gpa > 4)`।

**৪. `NOT` দিয়ে `NULL` ধরার চেষ্টা।** `NOT gpa >= 4` কখনো `NULL` GPA-ওয়ালাদের আনবে না। তাদেরও চাইলে আলাদা করে লেখো: `OR gpa IS NULL`।

</BugMonster>

<Quest id="2" title="মনে মনে হিসাব">
MySQL চালানোর আগে অনুমান করো, এগুলোর উত্তর কী হবে: `SELECT 0 OR 1 AND 0;` আর `SELECT NOT 0 AND NULL;`। তারপর চালিয়ে মিলিয়ে নাও।

<Solution>
- `0 OR 1 AND 0` → আগে `1 AND 0` = 0, তারপর `0 OR 0` = **0**।
- `NOT 0 AND NULL` → আগে `NOT 0` = 1, তারপর `1 AND NULL` = **NULL**।
</Solution>

Query লেখো, আর বন্ধনী ছাড়া লিখলে কী ভুল হতো, সেটাও ব্যাখ্যা করো।

<Solution title="ইঙ্গিত">
`AND` আগে কাজ করে, `OR` পরে। "হয় এটা, নয়তো ওটা" অংশটা বন্ধনীতে না রাখলে `OR`-এর পরের অংশ বাকি সব শর্ত থেকে আলাদা হয়ে যায়। আর "GPA এখনো আসেনি" মানে `IS NULL`।
</Solution>

```sql
SELECT name, class, city, gpa FROM students
WHERE class IN (9, 10)
  AND city <> 'ঢাকা'
```

ফলাফল: মীম (সিলেট), জুবায়ের (খুলনা), ফারিহা (চট্টগ্রাম)। আরিফ বাদ, কারণ তার GPA 2.90।

</Solution>
</Boss>
