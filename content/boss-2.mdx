## রাউন্ড ১: ডিজাইন

তিনটা টেবিল: বই, সদস্য, আর ধার (কে কোন বই কবে নিল, কবে ফেরত দিল)।

```sql
CREATE DATABASE library CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE library;

CREATE TABLE books (
  id       INT AUTO_INCREMENT PRIMARY KEY,
  title    VARCHAR(200) NOT NULL,
  author   VARCHAR(100) NOT NULL,
  category VARCHAR(50)  NOT NULL,
  copies   TINYINT UNSIGNED NOT NULL DEFAULT 1 CHECK (copies >= 1)
);

CREATE TABLE members (
  id        INT AUTO_INCREMENT PRIMARY KEY,
  name      VARCHAR(100) NOT NULL,
  type      ENUM('ছাত্র', 'শিক্ষক') NOT NULL,
  phone     VARCHAR(15) UNIQUE,
  joined_on DATE NOT NULL
);

CREATE TABLE loans (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  book_id     INT  NOT NULL,
  member_id   INT  NOT NULL,
  borrowed_on DATE NOT NULL,
  due_on      DATE NOT NULL,
  returned_on DATE NULL,            -- NULL মানে এখনো ফেরত দেয়নি
  CHECK (due_on > borrowed_on),
  CHECK (returned_on IS NULL OR returned_on >= borrowed_on),
  FOREIGN KEY (book_id)   REFERENCES books(id),
  FOREIGN KEY (member_id) REFERENCES members(id)
);
```

নতুন জিনিস **`ENUM`**: নির্দিষ্ট কয়েকটা মানের মধ্যে একটা। `type`-এ 'ছাত্র' বা 'শিক্ষক' ছাড়া কিছু বসবে না।

`loans`-এ কেন `(book_id, member_id)` Primary Key না? কারণ একই সদস্য একই বই একাধিকবার ধার নিতে পারে (রাফি পথের পাঁচালী সেপ্টেম্বরেও নিয়েছে, পরেও নিতে পারে)। প্রতিটা ধার একটা আলাদা ঘটনা, তাই আলাদা `id`।

## রাউন্ড ২: আপার রোজকার প্রশ্ন

<Solution>
```sql
SELECT m.name, b.title, l.due_on,
       DATEDIFF('2026-11-16', l.due_on) AS days_late,
       DATEDIFF('2026-11-16', l.due_on) * 5 AS fine

JOIN books b   ON b.id = l.book_id
JOIN members m ON m.id = l.member_id
WHERE l.returned_on IS NULL AND l.due_on < '2026-11-16'
ORDER BY days_late DESC;
```

<Quest id="4" title="তাকে কয় কপি আছে?">

       b.copies - COUNT(l.id) AS available

ORDER BY b.id;

কোন সদস্য এখনো একবারও বই নেয়নি? `NOT EXISTS` দিয়ে।

## রাউন্ড ৩: হেডস্যারের রিপোর্ট

<Quest id="7" title="কে দেরি করে ফেরত দেয়?">
যারা অন্তত একবার মেয়াদ পেরিয়ে বই ফেরত দিয়েছে, আর কতবার।

<Solution>
```sql
SELECT m.name, COUNT(*) AS late_returns
FROM loans l
JOIN members m ON m.id = l.member_id
WHERE l.returned_on > l.due_on
GROUP BY m.id, m.name
ORDER BY m.name;
```

নুসরাত ১ (দেবদাস), রাফি ১ (শেষের কবিতা)। যারা এখনো ফেরত দেয়নি, তাদের `returned_on` `NULL`, তাই তারা এখানে আসেনি; তাদের খোঁজ রাউন্ড ২-এর জরিমানার খাতায়।
</Solution>
</Quest>

<Quest id="8" title="ছাত্র বনাম শিক্ষক">
ছাত্র আর শিক্ষকরা আলাদাভাবে মোট কয়বার বই নিয়েছেন, আর ফেরত দেওয়া বইগুলো গড়ে কত দিন রেখেছিলেন।

<Solution>
```sql
SELECT m.type, COUNT(l.id) AS loans,
       ROUND(AVG(DATEDIFF(l.returned_on, l.borrowed_on)), 1) AS avg_days
FROM members m
JOIN loans l ON l.member_id = m.id
GROUP BY m.type;
```

| type | loans | avg_days |
| --- | --- | --- |
| ছাত্র | 7 | 16.0 |
| শিক্ষক | 4 | 25.0 |

গড়ে শুধু ফেরত দেওয়া বইগুলো গোনা হয়েছে, কারণ ফেরত না দিলে `DATEDIFF`-এর ফলাফল `NULL`, আর `AVG` `NULL` উপেক্ষা করে। লেভেল ৭-এর নিয়ম এখানে সুবিধা দিল।
</Solution>
</Quest>

<Boss title="তিন মাথার দানব">
হেডস্যারের শেষ তিনটা প্রশ্ন, প্রতিটা এক Query-তে:

1. কোন লেখকের অন্তত ২টা বই লাইব্রেরিতে আছে, আর তাঁদের বইগুলো মোট কতবার ধার হয়েছে?
2. সবচেয়ে বেশি বার বই নিয়েছে কে? সমান হলে সবাই আসবে।
3. প্রতিটা সদস্যের জন্য একটা স্ট্যাটাস: "জরিমানা বাকি" (মেয়াদোত্তীর্ণ বই হাতে), "বই হাতে আছে", "পরিষ্কার" (কিছু হাতে নেই), বা "নতুন" (কখনো নেয়নি)।

<Solution title="ইঙ্গিত ১">
প্রশ্ন ১: `books` থেকে `LEFT JOIN loans`, লেখক ধরে দল। বই গুনতে `COUNT(DISTINCT b.id)`, কারণ একটা বই অনেকবার ধার হলে তার অনেক Row।
</Solution>

<Solution title="ইঙ্গিত ২">
প্রশ্ন ২: "সমান হলে সবাই", তাই `LIMIT 1` না; সর্বোচ্চ সংখ্যাটা Subquery-তে বের করে `HAVING COUNT(*) = (...)`। প্রশ্ন ৩: একটা `CASE`, শর্তগুলো কড়া থেকে নরম ক্রমে, প্রতিটা `EXISTS` দিয়ে।
</Solution>

<Solution>
**১.** লেখকের দল, কিন্তু ধারের সংখ্যাও লাগবে, তাই `LEFT JOIN`:

```sql
SELECT b.author, COUNT(DISTINCT b.id) AS books, COUNT(l.id) AS loans
FROM books b
LEFT JOIN loans l ON l.book_id = b.id
GROUP BY b.author
HAVING COUNT(DISTINCT b.id) >= 2
ORDER BY loans DESC;
```

রবীন্দ্রনাথ ঠাকুর (৩টা বই, ৫ বার), বিভূতিভূষণ (২টা, ৩ বার), নজরুল (২টা, ১ বার)। JOIN-এর পর বই একাধিকবার আসে, তাই বই গুনতে `COUNT(DISTINCT b.id)`।

**২.** "সর্বোচ্চ" খুঁজতে Derived Table-এর ভেতর `MAX`:

```sql
SELECT m.name, COUNT(*) AS loans
FROM members m
JOIN loans l ON l.member_id = m.id
GROUP BY m.id, m.name
HAVING COUNT(*) = (
  SELECT MAX(c) FROM (SELECT COUNT(*) AS c FROM loans GROUP BY member_id) AS t
);
```

রাফি, ৩ বার। `ORDER BY ... LIMIT 1` দিলে সমান সংখ্যার দ্বিতীয়জন হারিয়ে যেত।

**৩.** প্রতিটা সদস্যের জন্য দুটো Correlated Subquery আর একটা `CASE`:

```sql
SELECT m.name,
  CASE
    WHEN EXISTS (SELECT 1 FROM loans l WHERE l.member_id = m.id
                 AND l.returned_on IS NULL AND l.due_on < '2026-11-16') THEN 'জরিমানা বাকি'
    WHEN EXISTS (SELECT 1 FROM loans l WHERE l.member_id = m.id
                 AND l.returned_on IS NULL) THEN 'বই হাতে আছে'
    WHEN EXISTS (SELECT 1 FROM loans l WHERE l.member_id = m.id) THEN 'পরিষ্কার'
    ELSE 'নতুন'
  END AS status
FROM members m
ORDER BY m.id;
```

| name | status |
| --- | --- |
| রাফি | জরিমানা বাকি |
