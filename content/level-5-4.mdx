## (i) কখনো অর্ডার দেননি (Relational Algebra)

**দ্রুত পথ:** [এই প্রশ্নের টেমপ্লেট খোলো](/templates?p=not-exists), নিজের নাম বসিয়ে চালাও। নিচে পুরো ভাঙা, ধাপে ধাপে।

### ধাপ ১: নিজের ভাষায় বলো

"যে ক্রেতাদের একটাও অর্ডার নেই, তাঁদের আইডি আর নাম।" আর লিখতে হবে **Relational Algebra**-তে, SQL-এ না।

### ধাপ ২: শব্দ দাগাও

| প্রশ্নের অংশ | মানে | Relational Algebra-তে |
| --- | --- | --- |
| "ID and name" | আউটপুটের Column | Projection: π<sub>cust_id, cname</sub> |
| "each customer" | সব ক্রেতা থেকে শুরু | `customer` |
| "never placed an order" | যাঁদের অর্ডার **আছে**, তাঁদের বাদ | বিয়োগ (Set Difference): **−** |

"Never", "কখনো না", "একটাও না": এই শব্দ মানেই অনস্তিত্ব (লেভেল ৪.৪-এর নকশা ২)। Relational Algebra-তে "না" লেখার একটাই অস্ত্র: **বিয়োগ**। সবাই − যাঁদের আছে = যাঁদের নেই।

### ধাপ ৩: হাতে উত্তর

সব ক্রেতা: ১, ২, ৩, ৪, ৫, ৬, ৭। `orders`-এ যাঁদের `cust_id` আছে: ১, ২, ৩, ৪, ৫। বিয়োগ: **৬ (Farzana), ৭ (Gias)**।

### ধাপ ৪: ধাপে ধাপে বানাও

<Flow steps={[
  "সব ক্রেতার আইডি: π cust_id (customer) → {1,2,3,4,5,6,7}",
  "অর্ডার দেওয়া আইডি: π cust_id (orders) → {1,2,3,4,5}",
  "বিয়োগ: π cust_id (customer) − π cust_id (orders) → {6,7}",
  "নাম পেতে customer-এর সাথে জোড়া: (ফলাফল) ⋈ customer",
  "শেষে: π cust_id, cname"
]} />

বিয়োগের আগে **দুই পাশ থেকেই শুধু `cust_id`** নিলাম। কেন? বিয়োগ (আর ∪, ∩) শুধু তখনই চলে যখন দুই পাশের Column-এর সংখ্যা আর ধরন এক। একে বলে **Union Compatibility**। `π cust_id, cname (customer) − π cust_id (orders)` লেখা **অবৈধ**: বাঁ পাশে দুটো Column, ডান পাশে একটা। তাই আগে শুধু আইডিতে বিয়োগ, তারপর Natural Join (⋈) দিয়ে নাম ফিরিয়ে আনা।

### উত্তর

<div className="brut-sm bg-yellow-soft px-5 py-4 text-center font-code text-lg leading-loose">
  π<sub>cust_id, cname</sub> ( customer ⋈ ( π<sub>cust_id</sub>(customer) − π<sub>cust_id</sub>(orders) ) )
</div>

ধাপে ধাপে লিখতে চাইলে (খাতায় এটা আরো পরিষ্কার দেখায়):

```text
r1 ← π cust_id (customer)
r2 ← π cust_id (orders)
r3 ← r1 − r2
result ← π cust_id, cname (r3 ⋈ customer)
```

### আলোচনা

**আরেকটা বৈধ রূপ:** যাঁদের অর্ডার আছে, তাঁদের আইডি আর নাম বের করে পুরো তালিকা থেকে বিয়োগ। এবার দুই পাশেই দুটো Column, তাই বৈধ:

<div className="brut-sm bg-card px-5 py-4 text-center font-code text-lg leading-loose">
  π<sub>cust_id, cname</sub>(customer) − π<sub>cust_id, cname</sub>(customer ⋈ orders)
</div>

**এই Algebra-টা SQL-এ চালিয়ে দেখি।** প্রশ্ন SQL চায়নি, কিন্তু নিজের উত্তর যাচাই করতে Algebra-কে হুবহু SQL-এ অনুবাদ করা যায়। বিয়োগ (−) মানে SQL-এর `EXCEPT` (MySQL 8.0.31 থেকে, MariaDB 10.3 থেকে):

<Run db="q3-shop">
```sql
-- π cust_id, cname (customer ⋈ (π cust_id (customer) − π cust_id (orders)))
SELECT c.cust_id, c.cname
FROM customer c
JOIN (
  SELECT cust_id FROM customer
  EXCEPT
  SELECT cust_id FROM orders
) r3 ON r3.cust_id = c.cust_id
ORDER BY c.cust_id;
```
</Run>

| cust_id | cname |
| --- | --- |
| 6 | Farzana |
| 7 | Gias |

আর প্রতিদিনের SQL-এ একই কথা সবচেয়ে বেশি লেখা হয় `NOT EXISTS` দিয়ে:

<Run db="q3-shop">
```sql
SELECT c.cust_id, c.cname
FROM customer c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.cust_id = c.cust_id)
ORDER BY c.cust_id;
```
</Run>

| Relational Algebra | SQL |
| --- | --- |
| π<sub>cols</sub>(R) | `SELECT DISTINCT cols FROM R` |
| σ<sub>শর্ত</sub>(R) | `WHERE শর্ত` |
| R ⋈ S | `JOIN ... ON` (একই নামের Column-এ) |
| R − S | `EXCEPT`, বা `NOT EXISTS` / `LEFT JOIN ... IS NULL` |

<BugMonster title="(i)-এর ফাঁদ">

**১. Union Compatibility ভাঙা।** `π cust_id, cname (customer) − π cust_id (orders)`: দুই পাশের Column আলাদা, তাই বিয়োগ অর্থহীন। পরীক্ষায় এটাই সবচেয়ে বেশি কাটা যায়।

**২. σ দিয়ে "না" লেখার চেষ্টা।** `σ cust_id ≠ orders.cust_id (customer × orders)`: এটা "অন্তত একটা অর্ডার আছে যেটা তাঁর না", মানে প্রায় সবাই। এক Row ধরে "না" মিলিয়ে "কোথাও নেই" পাওয়া যায় না; সেজন্যই বিয়োগ।

**৩. প্রশ্ন Algebra চেয়েছে, SQL লিখে দেওয়া।** উত্তরে SQL দিলে নম্বর কাটা যেতে পারে। Algebra লেখো; SQL শুধু নিজের যাচাইয়ের জন্য।

</BugMonster>

## (ii) ২০২৫-এ ক্যাটাগরি অনুযায়ী বিক্রি, ৫০,০০০-এর বেশি

**দ্রুত পথ:** [এই প্রশ্নের টেমপ্লেট খোলো](/templates?p=group-having), নিজের নাম বসিয়ে চালাও। নিচে পুরো ভাঙা, ধাপে ধাপে।

### ধাপ ১: নিজের ভাষায় বলো

"শুধু ২০২৫ সালের অর্ডার নিয়ে, প্রতিটা ক্যাটাগরিতে মোট কত টাকার বিক্রি (দাম × পরিমাণ) হয়েছে বের করো; যেসব ক্যাটাগরির মোট ৫০,০০০-এর **বেশি**, শুধু সেগুলো দেখাও।" প্রতিটা Row = একটা **ক্যাটাগরি**।

### ধাপ ২: শব্দ দাগাও

| প্রশ্নের অংশ | মানে | SQL-এ |
| --- | --- | --- |
| "price × quantity" | দুই টেবিলের Column | `orders JOIN product`, তারপর `p.price * o.quantity` |
| "total ... of each product category" | ক্যাটাগরি ধরে দল, তারপর যোগ | `GROUP BY p.category`, `SUM(...)` |
| "in the year 2025" | **প্রতিটা অর্ডারের** শর্ত (দলের আগে) | `WHERE o.order_date ...` |
| "only the categories whose total exceeds 50,000" | **দলের** শর্ত (যোগের পরে) | `HAVING SUM(...) > 50000` |

এটাই এই প্রশ্নের মূল শিক্ষা: **কোন শর্ত কখন খাটবে।** তারিখটা একেকটা অর্ডারের গুণ, তাই যোগ করার **আগে** ছাঁকতে হবে (`WHERE`)। মোট ৫০,০০০ হলো একটা দলের গুণ, যেটা যোগ করার **পরেই** জানা যায় (`HAVING`)। লেভেল ৮-এর ক্রম মনে করো: `FROM → WHERE → GROUP BY → HAVING → SELECT`।

### ধাপ ৩: হাতে উত্তর

শুধু ২০২৫-এর ১১টা অর্ডার, প্রতিটার অঙ্ক:

| ক্যাটাগরি | অর্ডার (দাম × পরিমাণ) | মোট |
| --- | --- | --- |
| Electronics | #1: 95000×1, #2: 28000×2, #8: 3500×2, #14: 95000×1 | 253000 |
| Furniture | #3: 12000×2, #5: 9500×3, #7: 7000×2 | 66500 |
| Clothing | #4: 2500×4, #6: 4500×3, #10: 2500×6 | 38500 |
| Appliances | #9: 12500×4 | 50000 |

৫০,০০০-এর **বেশি**: **Electronics, Furniture**। Appliances ঠিক ৫০,০০০, তাই বাদ।

### ধাপ ৪: ধাপে ধাপে বানাও

প্রথমে শুধু জোড়া, ছাঁকা আর প্রতিটা অর্ডারের অঙ্ক। এখনো কোনো দল নেই:

<Run db="q3-shop">
```sql
SELECT o.order_id, o.order_date, p.category, p.price, o.quantity,
       p.price * o.quantity AS amount
FROM orders o
JOIN product p ON p.prod_id = o.prod_id
WHERE o.order_date >= '2025-01-01'
  AND o.order_date <  '2026-01-01'
ORDER BY p.category, o.order_id;
```
</Run>

১১টা Row, প্রতিটার অঙ্ক হাতের টেবিলের সাথে মিলিয়ে নাও। 2025-12-31-এর অর্ডার (#10) আছে, 2026-01-02-এরটা (#12) নেই: সীমানা ঠিক। এবার দল বাঁধি, এখনো `HAVING` ছাড়া:

<Run db="q3-shop">
```sql
SELECT p.category, SUM(p.price * o.quantity) AS total_sales
FROM orders o
JOIN product p ON p.prod_id = o.prod_id
WHERE o.order_date >= '2025-01-01'
  AND o.order_date <  '2026-01-01'
GROUP BY p.category
ORDER BY total_sales DESC;
```
</Run>

চারটা ক্যাটাগরি, হাতের মোটের সাথে মিলেছে। শেষ ধাপে দলের শর্ত:

### উত্তর

<Run db="q3-shop">
```sql
SELECT p.category, SUM(p.price * o.quantity) AS total_sales
FROM orders o
JOIN product p ON p.prod_id = o.prod_id
WHERE o.order_date >= '2025-01-01'
  AND o.order_date <  '2026-01-01'
GROUP BY p.category
HAVING SUM(p.price * o.quantity) > 50000
ORDER BY total_sales DESC;
```
</Run>

| `o.order_date >= '2025-01-01' AND o.order_date < '2026-01-01'` | হ্যাঁ | সবচেয়ে ভালো: Index কাজে লাগে, আর `DATETIME` হলেও শেষ দিনের সব সময় ধরে |
| `YEAR(o.order_date) = 2025` | হ্যাঁ | পড়তে সহজ, পরীক্ষায় পূর্ণ নম্বর; কিন্তু Column-কে Function-এ মুড়ায় Index কাজ করে না (লেভেল ১৬) |
| `o.order_date BETWEEN '2025-01-01' AND '2025-12-31'` | এখানে হ্যাঁ | `DATE`-এ ঠিক; Column `DATETIME` হলে `2025-12-31 14:30` বাদ পড়ে যায় |

`YEAR()` দিয়েও চালিয়ে দেখো, একই উত্তর আসবে (এই পাতার ইঞ্জিনেও `YEAR` চলে):

<Run db="q3-shop">
```sql
SELECT p.category, SUM(p.price * o.quantity) AS total_sales
FROM orders o
JOIN product p ON p.prod_id = o.prod_id
WHERE YEAR(o.order_date) = 2025
GROUP BY p.category
HAVING total_sales > 50000;
```
</Run>

এখানে `HAVING total_sales > 50000`, মানে `SELECT`-এর Alias দিয়ে লেখা: MySQL এটা মেনে নেয় (স্ট্যান্ডার্ড SQL-এ নিষেধ, তাই খাতায় পুরো `SUM(...)` লেখাই নিরাপদ)।

<BugMonster title="(ii)-এর ফাঁদ">

**১. যোগফল `WHERE`-এ।** `WHERE SUM(p.price * o.quantity) > 50000` → `ERROR 1111: Invalid use of group function`। `WHERE` চলার সময় যোগফল এখনো তৈরিই হয়নি।

**২. বছরের শর্ত ভুলে যাওয়া।** তাহলে সব বছরের যোগ আসে, আর **Clothing** (মোট ৫৬,৫০০) ভুল করে ঢুকে যায়। নিচে চালিয়ে দেখো।

**৩. বছরের শর্ত `HAVING`-এ।** `HAVING YEAR(o.order_date) = 2025`: দলের ভেতরে অনেক তারিখ, কোনটা দেখবে? MySQL হয় error দেয় (`ONLY_FULL_GROUP_BY`), নয়তো যেকোনো একটা Row-এর তারিখ দেখে চুপচাপ ভুল উত্তর দেয়। Row-এর শর্ত সবসময় `WHERE`-এ।

**৪. `>=` লেখা।** "exceeds" মানে বেশি। `>=` দিলে Appliances (ঠিক ৫০,০০০) চলে আসে।

**৫. `SUM(p.price) * SUM(o.quantity)`।** যোগফলের গুণ আর গুণফলের যোগ এক না। প্রতিটা অর্ডারে আগে গুণ, তারপর যোগ: `SUM(p.price * o.quantity)`।

</BugMonster>

<Run db="q3-shop">
```sql
-- ভুল: বছরের শর্ত নেই
SELECT p.category, SUM(p.price * o.quantity) AS total_sales
FROM orders o
JOIN product p ON p.prod_id = o.prod_id
GROUP BY p.category
HAVING SUM(p.price * o.quantity) > 50000
ORDER BY total_sales DESC;
```
</Run>

## (iii) সবচেয়ে দামি পণ্যের ক্রেতা

**দ্রুত পথ:** [এই প্রশ্নের টেমপ্লেট খোলো](/templates?p=exists), নিজের নাম বসিয়ে চালাও। নিচে পুরো ভাঙা, ধাপে ধাপে।

### ধাপ ১: নিজের ভাষায় বলো

"দোকানের সবচেয়ে দামি পণ্য কোনটা? যাঁরা সেটা (কখনো, যেকোনো বছরে) অর্ডার করেছেন, তাঁদের নাম আর শহর।" প্রতিটা Row = একজন ক্রেতা, একবার।

### ধাপ ২: শব্দ দাগাও আর ছোট প্রশ্নে ভাঙো

এই প্রশ্নে আসলে **তিনটা** ছোট প্রশ্ন একটার ভেতরে আরেকটা:

1. সর্বোচ্চ দাম কত? → `SELECT MAX(price) FROM product`
2. কোন পণ্য(গুলো)র দাম সেটা? → `WHERE price = (১-এর উত্তর)`
3. কারা সেগুলো অর্ডার করেছেন? → `orders`-এ `prod_id` মেলাও, তারপর `customer` থেকে নাম-শহর

"the most expensive product" একবচনে লেখা, কিন্তু সর্বোচ্চ দামে **একাধিক** পণ্য থাকতেই পারে। এই ডেটায় আছে দুটো।

### ধাপ ৩: হাতে উত্তর

সর্বোচ্চ দাম ৯৫,০০০: পণ্য ১ (Laptop Pro 14) আর ২ (Gaming Laptop X)। `orders`-এ এ দুটো যাঁরা কিনেছেন: Ayesha (#1: পণ্য ১, #14: পণ্য ২), Dipu (#11: পণ্য ২), Bashir (#13: পণ্য ১)। উত্তর: **Ayesha (Dhaka), Bashir (Chattogram), Dipu (Sylhet)**, প্রত্যেকে একবার।

### ধাপ ৪: ধাপে ধাপে বানাও

ছোট প্রশ্ন ১ আর ২ একসাথে:

<Run db="q3-shop">
```sql
SELECT prod_id, pname, price
FROM product
WHERE price = (SELECT MAX(price) FROM product);
```
</Run>

দুটো পণ্য। ছোট প্রশ্ন ৩-এর জন্য এটাকে `IN (...)`-এর ভেতরে বসাই, কারণ উত্তর একাধিক হতে পারে (`=` দিলে MySQL বলত `Subquery returns more than 1 row`):

<Run db="q3-shop">
```sql
SELECT c.cname, c.city, o.order_id, o.prod_id
FROM customer c
JOIN orders o ON o.cust_id = c.cust_id
WHERE o.prod_id IN (
  SELECT prod_id FROM product
  WHERE price = (SELECT MAX(price) FROM product)
)
ORDER BY c.cust_id;
```
</Run>

চারটা Row: Ayesha দুবার (দুটো ল্যাপটপই কিনেছেন)। প্রশ্ন চায় "each customer" একবার, আর শুধু নাম-শহর।

### উত্তর

<Run db="q3-shop">
```sql
SELECT c.cname, c.city
FROM customer c
WHERE EXISTS (
  SELECT 1
  FROM orders o
  WHERE o.cust_id = c.cust_id
    AND o.prod_id IN (
      SELECT prod_id FROM product
      WHERE price = (SELECT MAX(price) FROM product)
    )
)
ORDER BY c.cust_id;
```
</Run>

| cname | city |
| --- | --- |
| Ayesha | Dhaka |
| Bashir | Chattogram |
| Dipu | Sylhet |

`EXISTS` বাইরে শুধু `customer` রাখে, তাই ডুপ্লিকেটের প্রশ্নই নেই। ধাপ ৪-এর JOIN-রূপে `SELECT DISTINCT c.cname, c.city` লিখলেও একই উত্তর; তবে একই নাম-শহরের দুজন আলাদা ক্রেতা থাকলে `DISTINCT` তাঁদের এক করে ফেলত, `EXISTS` ফেলত না।

### আলোচনা

**তিন তলাকে JOIN দিয়ে সমতল করা:** একই কাজ সব টেবিল একসাথে জুড়ে:

<Run db="q3-shop">
```sql
SELECT DISTINCT c.cust_id, c.cname, c.city
FROM customer c
JOIN orders  o ON o.cust_id = c.cust_id
JOIN product p ON p.prod_id = o.prod_id
WHERE p.price = (SELECT MAX(price) FROM product)
ORDER BY c.cust_id;
```
</Run>

এখানে `cust_id`-ও `SELECT`-এ রাখলাম, যাতে `DISTINCT` একই নামের দুজনকে মিশিয়ে না ফেলে।

<BugMonster title="(iii)-এর ফাঁদ">

**১. `ORDER BY price DESC LIMIT 1`।** সমান দামের দুটো পণ্য থাকলে একটা চুপচাপ বাদ পড়ে, আর সেটার ক্রেতাও। নিচের ভুল Query চালিয়ে দেখো: তিনজনের জায়গায় দুজন।

**২. `= (SELECT prod_id ...)`।** দুটো পণ্য ফেরত এলে `ERROR 1242: Subquery returns more than 1 row`। একাধিক মান সম্ভব হলে `IN`।

**৩. (ii)-এর বছর এখানেও বসানো।** এই প্রশ্নে কোনো সময়ের কথা নেই। ২০২৫ দিয়ে ছাঁকলে Dipu (২০২৪) আর Bashir (২০২৬) দুজনেই বাদ পড়েন। আগের উপ-প্রশ্নের শর্ত পরেরটায় টেনে আনা পরীক্ষার খুব সাধারণ ভুল।

**৪. "সবচেয়ে বেশি টাকার অর্ডার" ভেবে ফেলা।** প্রশ্ন বলেছে সবচেয়ে **দামি পণ্য** (`price`), সবচেয়ে বড় অর্ডার (`price × quantity`) না।

</BugMonster>

<Run db="q3-shop">
```sql
-- ভুল: LIMIT 1 সমান দামের দ্বিতীয় পণ্যটা ফেলে দেয়
SELECT DISTINCT c.cname, c.city
FROM customer c
JOIN orders o ON o.cust_id = c.cust_id
WHERE o.prod_id = (SELECT prod_id FROM product ORDER BY price DESC LIMIT 1);
```
</Run>

দুজন। আর **কোন** দুজন, সেটাও নিশ্চিত না: সমান দামে কোন ল্যাপটপ "প্রথম", তা ইঞ্জিন নিজের মতো ঠিক করে। এই পাতার ইঞ্জিনে Dipu হারান; একই Query MariaDB-তে চালিয়ে দেখেছি, সেখানে হারান Bashir। যে উত্তর চালানো ভেদে বদলায়, সেটা উত্তরই না।

<Remember>
**"সবচেয়ে বেশি/কম" প্রশ্নে `LIMIT 1` না, `= (SELECT MAX(...))`।** সমান মান থাকলে `LIMIT 1` একজনকে চুপচাপ বাদ দেয়, আর ফলাফলে কোনো error থাকে না যে ধরবে।
</Remember>
