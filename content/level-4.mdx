<Mission>
- `LIKE` দিয়ে "এমন কিছু" খোঁজা: যার নাম "ফ" দিয়ে শুরু, যার নম্বর 017 দিয়ে
- `IN` দিয়ে লম্বা `OR`-এর ঝামেলা কমানো
- `BETWEEN` দিয়ে একটা সীমার ভেতরে খোঁজা
- `NULL`-এর রহস্য: কেন `= NULL` কখনো কাজ করে না
</Mission>

লেভেল ৩-এর `WHERE` দিয়ে সব খোঁজাই যায়, কিন্তু কিছু খোঁজা লিখতে লম্বা হয়ে যায়। এই লেভেলে চারটা শর্টকাট শিখব। (ডেটা লেভেল ২-এর মতোই থাকতে হবে।)

## LIKE: আংশিক মিল

দুটো বিশেষ চিহ্ন (**Wildcard**) দিয়ে প্যাটার্ন বানানো হয়:

| চিহ্ন | মানে | উদাহরণ | মিলবে |
| --- | --- | --- | --- |
| `%` | যেকোনো কিছু, শূন্য বা অনেক অক্ষর | `'ফ%'` | ফারিহা, ফাহিম, ফ |
| `_` | ঠিক একটা অক্ষর | `'_ী_'` | মীম |

```sql
-- যাদের নাম "ফ" দিয়ে শুরু
SELECT name FROM students WHERE name LIKE 'ফ%';
```

| name |
| --- |
| ফারিহা |

```sql
-- যাদের গ্রামীণফোন নম্বর (017 দিয়ে শুরু)
SELECT name, phone FROM students WHERE phone LIKE '017%';
```

| name | phone |
| --- | --- |
| রাফি | 01711000001 |
| লামিয়া | 01711000010 |

```sql
-- যাদের নামের যেকোনো জায়গায় "ি"-কার আছে
SELECT name FROM students WHERE name LIKE '%ি%';
```

| name |
| --- |
| রাফি |
| আরিফ |
| সাদিয়া |
| ফারিহা |
| লামিয়া |

<Note title="বাংলায় _ একটু সাবধানে">
কম্পিউটারের কাছে "মী" দুটো অক্ষর: `ম` আর `ী`-কার। তাই `'_ী_'` মিলল "মীম"-এর সাথে (ম + ী + ম = ৩টা অক্ষর)। আমাদের চোখে যেটা একটা যুক্তাক্ষর, Database-এর কাছে সেটা প্রায়ই দুই-তিনটা অক্ষর। বাংলা লেখায় `_`-এর চেয়ে `%` নিরাপদ।
</Note>

ইংরেজিতে `LIKE` সাধারণত বড়-ছোট হাতের পার্থক্য করে না (`_ci` collation-এ): `'rafi%'` মিলবে `Rafi`-র সাথেও। `ci` মানে case-insensitive।

## IN: তালিকার যেকোনোটা

ঢাকা, সিলেট বা খুলনার ছাত্ররা? `OR` দিয়ে লিখলে:

```sql
SELECT name, city FROM students
WHERE city = 'ঢাকা' OR city = 'সিলেট' OR city = 'খুলনা';
```

`IN` দিয়ে একই কাজ, অনেক পরিষ্কার:

```sql
SELECT name, city FROM students WHERE city IN ('ঢাকা', 'সিলেট', 'খুলনা');
```

| name | city |
| --- | --- |
| রাফি | ঢাকা |
| তানভীর | ঢাকা |
| মীম | সিলেট |
| সাদিয়া | ঢাকা |
| জুবায়ের | খুলনা |
| ইমরান | ঢাকা |

উল্টোটা `NOT IN`:

```sql
SELECT name, city FROM students WHERE city NOT IN ('ঢাকা', 'চট্টগ্রাম');
```

| name | city |
| --- | --- |
| মীম | সিলেট |
| আরিফ | রাজশাহী |
| জুবায়ের | খুলনা |
| লামিয়া | বরিশাল |

## BETWEEN: সীমার ভেতরে

```sql
SELECT name, gpa FROM students WHERE gpa BETWEEN 3.50 AND 4.50;
```

| name | gpa |
| --- | --- |
| রাফি | 4.50 |
| তানভীর | 3.75 |
| মীম | 4.25 |
| জুবায়ের | 3.50 |
| ইমরান | 4.00 |

`BETWEEN a AND b` মানে `>= a AND <= b`, দুই প্রান্তই **ভেতরে**। তাই 3.50 আর 4.50 দুটোই এসেছে। তারিখেও চলে:

```sql
-- ২০১০ সালে যাদের জন্ম
SELECT name, birth_date FROM students
WHERE birth_date BETWEEN '2010-01-01' AND '2010-12-31';
```

| name | birth_date |
| --- | --- |
| তানভীর | 2010-12-25 |
| মীম | 2010-05-19 |
| সাদিয়া | 2010-01-08 |

<Tip title="DATETIME-এ BETWEEN-এর ফাঁদ">
Column যদি `DATETIME` হয় (তারিখ + সময়), তাহলে `BETWEEN '2024-01-01' AND '2024-01-31'` লিখলে ৩১ জানুয়ারির রাত ১২টার পরের সব বাদ পড়ে যায়, কারণ `'2024-01-31'` মানে `2024-01-31 00:00:00`। নিরাপদ উপায়: **`>= '2024-01-01' AND < '2024-02-01'`**।
</Tip>

## NULL: "জানা নেই"-এর রহস্য

যাদের ফোন নম্বর নেই, তাদের খুঁজি:

```sql
SELECT name, phone FROM students WHERE phone = NULL;
```

ফলাফল: **একটাও Row আসে না!** অথচ তিনজনের নম্বর নেই। কেন?

`NULL` মানে "জানা নেই"। "জানা নেই" কি "জানা নেই"-এর সমান? উত্তরও "জানা নেই"। SQL-এ `NULL`-এর সাথে যেকোনো তুলনা (`=`, `<>`, `>`...) সত্যও না, মিথ্যাও না, বরং `NULL`, আর `WHERE` শুধু সত্যি হলেই Row নেয়। তাই `NULL` খুঁজতে আলাদা শব্দ আছে:

```sql
SELECT name, phone FROM students WHERE phone IS NULL;
```

| name | phone |
| --- | --- |
| তানভীর | NULL |
| আরিফ | NULL |
| ইমরান | NULL |

```sql
-- যাদের নম্বর আছে
SELECT name, phone FROM students WHERE phone IS NOT NULL;
```

ফলাফলে `NULL`-এর বদলে সুন্দর কিছু দেখাতে `IFNULL` (বা স্ট্যান্ডার্ড SQL-এর `COALESCE`):

```sql
SELECT name, IFNULL(phone, 'নম্বর নেই') AS phone
FROM students
WHERE class = 10;
```

| name | phone |
| --- | --- |
| জুবায়ের | 01511000007 |
| ফারিহা | 01311000008 |
| ইমরান | নম্বর নেই |

<Remember>
**`NULL` খুঁজতে সবসময় `IS NULL` বা `IS NOT NULL`। কখনো `= NULL` না।** আর মনে রেখো, `NULL` ≠ `0` ≠ `''`। GPA `0` মানে কেউ শূন্য পেয়েছে; GPA `NULL` মানে রেজাল্টই আসেনি।
</Remember>

<BugMonster title="শর্টকাটের ফাঁদ">

**১. `NOT IN` আর `NULL`-এর মারাত্মক জুটি।** তালিকায় একটা `NULL` থাকলে `NOT IN` কিছুই ফেরত দেয় না:

```sql
SELECT name FROM students WHERE city NOT IN ('ঢাকা', NULL);  -- কোনো Row আসবে না!
```

কারণ "সিলেট কি NULL-এর সমান না?" এর উত্তর "জানা নেই"। লেভেল ১২-এ Subquery-র সাথে এই ফাঁদে প্রায় সবাই একবার পড়ে।

**২. `BETWEEN`-এ ছোট-বড় উল্টো।** `BETWEEN 4.50 AND 3.50` কিছুই আনবে না। ছোটটা সবসময় আগে।

**৩. `LIKE` ছাড়া Wildcard।** `WHERE name = 'ফ%'` আক্ষরিক অর্থেই "ফ%" নামের কাউকে খুঁজবে। `%` শুধু `LIKE`-এর সাথে জাদু দেখায়।

**৪. `%` দিয়ে শুরু করা ধীর।** `LIKE '%ি%'` ঠিক উত্তর দেয়, কিন্তু টেবিলের প্রতিটা Row পড়ে। লাখো Row-এ এটা ধীর হয়ে যায়। লেভেল ১৬-এ Index-এর সাথে এর কারণ বুঝব।

</BugMonster>
